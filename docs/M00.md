# M00 implementation contracts

## Application boundary

`repo_repair.app.cli:app` is the Typer application installed as `repo-repair`.
`python -m repo_repair` invokes the same application.

| Interface | Contract |
| --- | --- |
| `--help` | Describe the available M00 commands without loading settings. |
| `--version` | Print the installed distribution version without loading settings. |
| `config` | Load and validate settings, then print JSON with `repo_path` and `log_level`. |
| `check [--repo PATH] [--json]` | Validate a readable directory, then report local project markers. |

`check --json` produces an object containing an absolute `repo_path` and three booleans:
`is_git_repository`, `has_pyproject`, and `has_tests`. These describe local marker existence,
not a full repository diagnosis. Exit statuses: 0 success, 1 repository path error,
2 command/configuration error. Errors go to stderr; JSON results go to stdout.

## Configuration boundary

`repo_repair.config.Settings` derives from Pydantic Settings. Callers may instantiate it
directly; settings are loaded at command invocation rather than import time. Fields:

- `repo_path: pathlib.Path`: expands `~` and resolves relative to the current directory.
- `log_level`: uppercase `DEBUG`, `INFO`, `WARNING`, `ERROR`, or `CRITICAL`.

Explicit values override environment, then cwd `.env`, then defaults. No settings singleton
is cached. The path need not exist at construction time; the CLI `check` owns validation
of the target directory. Configuration does not create directories or initialize logging.

## Test boundary

The main suite has isolated environment/cwd configuration and includes process-level tests
of the installed console script. The example is not imported by the application or the main
test suite. Its tests describe the intended `create_order` contract and deliberately fail for
non-positive inputs. Only explicit example test runs should be red at M00.

Future components in the architecture document are design intent, not M00 interfaces.
Define their contracts when their implementation milestones begin.
